## 4. Архітектура та ініціалізація

`X → Linear(4, 8) → ReLU → Linear(8, 3) → логіти`

| Параметр | Розмірність | Ініціалізація |
|---|---|---|
| W1 | 4 × 8 | He: 𝒩(0, σ²), σ = √(2/4) |
| b1 | 8 | нулі |
| W2 | 8 × 3 | Xavier: 𝒩(0, σ²), σ = √(2/(8+3)) |
| b2 | 3 | нулі |

Для ініціалізації створюється новий `default_rng(0)`, послідовно генеруються W1, потім W2.

## 5. Прямий прохід і функція втрат

N = 105, one-hot мітки Y ∈ {0,1}^{N×3}.

```
Z1 = X·W1 + b1          (N×8)
H  = max(Z1, 0)         (N×8)
Z2 = H·W2 + b2          (N×3)   — логіти
log p_nk = (Z2_nk − m_n) − log Σ_j exp(Z2_nj − m_n),   m_n = max_j Z2_nj
L = −(1/N) Σ_n log p_{n, y_n}
```

**Чисельна стабільність.** Softmax інваріантний до зсуву логітів на константу в межах рядка. Після віднімання максимуму найбільший показник експоненти дорівнює 0, тож `exp` не переповнюється, а сума під логарифмом ≥ 1, тому `log` не отримує 0. Втрата рахується через log-softmax, без явного `log(softmax)`, що уникає `log(0) = −∞`.

## 6. Зворотний прохід

**Градієнт за логітами.** Для одного об'єкта ∂(−log p_y)/∂z_k = p_k − y_k. З урахуванням усереднення:

```
dZ2 = (P − Y) / N                     (N×3)
dW2 = Hᵀ · dZ2                        (8×3)
db2 = Σ_n dZ2[n, :]                   (3,)
dH  = dZ2 · W2ᵀ                       (N×8)
dZ1 = dH ⊙ 1[Z1 > 0]                  (N×8)
dW1 = Xᵀ · dZ1                        (4×8)
db1 = Σ_n dZ1[n, :]                   (8,)
```

Сума за n у градієнтах зміщень виникає тому, що b додається до кожного рядка (broadcast), тож внески всіх об'єктів складаються. Похідна ReLU у точці 0 береться рівною 0, як у PyTorch.

### Розмірності

| Масив | Розмірність | Масив | Розмірність |
|---|---|---|---|
| X | 105 × 4 | P, Y, dZ2 | 105 × 3 |
| Z1, H, dH, dZ1 | 105 × 8 | **dW1** | 4 × 8 |
| Z2 | 105 × 3 | **db1** | 8 |
| | | **dW2** | 8 × 3 |
| | | **db2** | 3 |

Кожен градієнт має ту саму форму, що й відповідний параметр.

### Збережені проміжні значення (`cache`)

| Значення | Навіщо потрібне |
|---|---|
| `X` | dW1 = Xᵀ·dZ1 |
| `Z1` | маска похідної ReLU 1[Z1 > 0] |
| `H` | dW2 = Hᵀ·dZ2 |
| `P` | dZ2 = (P − Y)/N |
| `y` | побудова one-hot Y |

Z2 окремо не зберігається: для backward достатньо P. Параметри W2 беруться з моделі (для dH).

## 7. Звірка з PyTorch

Еквівалентна мережа `nn.Sequential(Linear(4,8), ReLU(), Linear(8,3))` у `float64`, втрата `F.cross_entropy(reduction="mean")`. Оскільки `nn.Linear` зберігає вагу як (out, in), у неї копіюється `W.T`, а градієнт `weight.grad` транспонується назад.

- Втрата NumPy: `1.4562007801142816`
- Втрата PyTorch: `1.4562007801142818`

| Величина | Максимальна абсолютна різниця NumPy / PyTorch | Перевірку пройдено |
|---|---|---|
| Втрата | 2.220e-16 | так |
| Градієнт W1 | 2.776e-17 | так |
| Градієнт b1 | 5.204e-17 | так |
| Градієнт W2 | 5.551e-17 | так |
| Градієнт b2 | 1.249e-16 | так |

Критерій: |a − b| ≤ 1e-12 для кожної пари елементів; усі значення скінченні. Різниці мають порядок машинного епсилону float64 (≈ 2.2e-16) і пояснюються лише іншим порядком операцій округлення.

## 8. Чисельна перевірка (ε = 1e-6)

g_num = (L(θ + ε) − L(θ − ε)) / (2ε); після обчислення параметр відновлюється.

| Параметр | Градієнт backward() | Чисельна похідна | Абсолютна різниця | Перевірку пройдено |
|---|---|---|---|---|
| W1[0, 0] | -1.992018433056e-02 | -1.992018439090e-02 | 6.034e-11 | так |
| b1[0] | -7.056611158438e-02 | -7.056611162071e-02 | 3.633e-11 | так |
| W2[0, 0] | 1.352302086055e-01 | 1.352302086977e-01 | 9.218e-11 | так |
| b2[0] | 8.552164484196e-02 | 8.552164498798e-02 | 1.460e-10 | так |

Критерій: |g_num − g_manual| ≤ 1e-7. Похибка ~1e-10 очікувана: похибка усічення центральної різниці O(ε²) ≈ 1e-12, а похибка округлення ≈ u·L/ε ≈ 2.2e-16·1.46/1e-6 ≈ 3e-10 домінує.

## 9. Дослід із навмисною помилкою

**Зміна:** у `backward()` прибрано ділення на N: `dZ2 = P − Y`. Функція втрат не змінювалась. Відтворення: `uv run python main.py --bug` (параметр `NumpyMLP(..., buggy=True)`); за замовчуванням працює правильна реалізація.

### Прогноз (записаний до запуску)

1. **Втрата не зміниться**: помилка лише в backward, forward і формула L ті самі.
2. **Усі ненульові градієнти збільшаться рівно в N = 105 разів.** dZ2 зросте в 105 разів, а всі наступні градієнти лінійні за dZ2 (множення на Hᵀ, W2ᵀ, маску ReLU, Xᵀ, сумування), тож множник пройде без змін. Нульові елементи (якби такі були, наприклад через «мертвий» нейрон) залишаться нулями.
3. **Помилку мають виявити**: звірка з PyTorch для всіх чотирьох градієнтів і чисельна перевірка для всіх чотирьох параметрів. Звірка втрати з PyTorch пройде, тож вона помилку не виявляє.

### Зіставлення з прогнозом

Прогноз підтвердився повністю. Чисельна похідна не змінилась, бо залежить лише від функції втрат, а не від backward. Саме тому вона є незалежним еталоном. Помилка такого типу (правильний напрям, неправильний масштаб) непомітна за самою втратою і лише рівносильна збільшенню learning rate у 105 разів, тому без градієнтних перевірок її легко пропустити. Після досліду правильна реалізація залишається реалізацією за замовчуванням.

## 10. Висновки

1. Реалізовано forward, стабільну крос-ентропію через log-softmax і ручний backprop двошарової мережі в NumPy без autograd.
2. Втрата і всі 67 елементів чотирьох градієнтів збігаються з PyTorch із похибкою ≤ 2.3e-16 (критерій 1e-12).
3. Центральна різниця для W1[0,0], b1[0], W2[0,0], b2[0] збігається з backward з похибкою ≤ 1.5e-10 (критерій 1e-7).
4. Навмисна помилка (без /N) не змінює втрату, але масштабує градієнти в N разів; її виявили обидва незалежні методи перевірки.
