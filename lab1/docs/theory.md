# Теоретичний довідник до ЛР1 (підготовка до захисту)

## 1. Звідки береться dZ2 = (P − Y)/N

Для одного об'єкта з логітами z ∈ ℝ³ і правильним класом y:

ℓ = −log p_y = −z_y + log Σ_j e^{z_j}.

∂ℓ/∂z_k = −1[k = y] + e^{z_k} / Σ_j e^{z_j} = p_k − y_k.

Через log-sum-exp похідна виходить без явного якобіана softmax. Якщо рахувати через якобіан ∂p_i/∂z_k = p_i(δ_ik − p_k), результат той самий: Σ_i (−y_i/p_i)·p_i(δ_ik − p_k) = −y_k + p_k Σ_i y_i = p_k − y_k.

Для середньої втрати L = (1/N) Σ_n ℓ_n кожен об'єкт отримує множник 1/N, звідси dZ2 = (P − Y)/N.

Властивості: сума кожного рядка P − Y дорівнює 0; |p_k − y_k| ≤ 1, тож градієнт за логітами обмежений.

## 2. Правило для афінного шару

Для Z = A·W + b (A: N×m, W: m×k, b: k) і відомого G = ∂L/∂Z (N×k):

| Градієнт | Формула | Мнемоніка форми |
|---|---|---|
| ∂L/∂W | Aᵀ·G | (m×N)(N×k) = m×k, як W |
| ∂L/∂b | Σ_n G[n,:] | k, як b |
| ∂L/∂A | G·Wᵀ | (N×k)(k×m) = N×m, як A |

Практичне правило: градієнт завжди має форму параметра; транспонування підбирається так, щоб розмірності збіглися. Виведення поелементно: Z_nj = Σ_i A_ni W_ij + b_j ⇒ ∂L/∂W_ij = Σ_n G_nj A_ni = (AᵀG)_ij.

## 3. ReLU

H = max(Z1, 0), ∂H/∂Z1 = 1[Z1 > 0] (поелементно). У точці 0 похідна не визначена; використовується субградієнт 0 (так робить PyTorch). Тому dZ1 = dH ⊙ 1[Z1 > 0]: градієнт проходить лише крізь активні нейрони.

«Мертвий» нейрон: якщо Z1[:, j] ≤ 0 для всіх об'єктів, стовпчик dZ1[:, j] = 0, отже db1[j] = 0 і стовпчик dW1[:, j] = 0. У нашому запуску мертвих нейронів немає (усі 8 елементів db1 ненульові).

## 4. Чисельна стабільність

- `exp(1000)` = inf у float64 (межа ≈ 709.8). Віднімання max робить усі показники ≤ 0.
- log-softmax: log p_k = z_k − m − log Σ_j e^{z_j − m}. Сума ≥ 1 (доданок для максимуму дорівнює e⁰ = 1), тож логарифм скінченний.
- Наївне `np.log(softmax(z))` може дати log(0) = −inf, якщо ймовірність класу занижена до underflow.

## 5. Ініціалізація

- **He** (Var = 2/fan_in) для шару перед ReLU: ReLU обнуляє приблизно половину входів, множник 2 компенсує це й зберігає дисперсію активацій.
- **Xavier/Glorot** (Var = 2/(fan_in + fan_out)): компроміс між збереженням дисперсії у прямому (1/fan_in) та зворотному (1/fan_out) проходах.
- Зміщення нулями: симетрію ламають випадкові ваги.

## 6. Чисельне диференціювання

| Схема | Формула | Похибка усічення |
|---|---|---|
| Пряма різниця | (L(θ+ε) − L(θ))/ε | O(ε) |
| Центральна | (L(θ+ε) − L(θ−ε))/(2ε) | O(ε²) |

Повна похибка ≈ C·ε² + u·|L|/ε, де u ≈ 1.1e-16 (одиниця округлення float64). Оптимум ε ≈ u^{1/3} ≈ 5e-6, тому ε = 1e-6 — розумний вибір, а досягнута похибка ~1e-10 узгоджується з оцінкою.

Обмеження: якщо зсув ±ε змінює знак якогось Z1 (перехід через злам ReLU), похідна з різниці може не збігатися з аналітичною. Для перевірки це нечасте явище, бо ймовірність |Z1| < ε мала.

Чому чисельна перевірка лише для кількох елементів: для кожного параметра потрібні 2 прямі проходи, тобто 2·P проходів для всіх P параметрів проти одного backward.

## 7. Чому допуски саме такі

- **1e-12 для PyTorch**: обидві реалізації рахують ту саму математику у float64; розбіжність лише від порядку операцій, ~1e-16. Допуск із великим запасом, але будь-яка логічна помилка дасть різницю на багато порядків більшу.
- **1e-7 для чисельної похідної**: сама чисельна похідна має похибку ~1e-10, тож потрібен ширший допуск.
- **float64** обов'язковий: у float32 u ≈ 6e-8, і чисельна похідна з ε = 1e-6 мала б похибку ~0.1, перевірка втратила б сенс.

## 8. Чому помилка без /N не видна у втраті

Forward не змінювався, тож L однакова. Градієнти лінійні за dZ2, тому всі вони множаться на N = 105 (напрям той самий, масштаб інший). Під час навчання це еквівалентно збільшенню learning rate у 105 разів. Виявити можна лише порівнянням градієнтів із незалежним еталоном: autograd або скінченними різницями.

## 9. Ймовірні питання на захисті

1. **Чому в dW1 саме Xᵀ·dZ1, а не dZ1·Xᵀ?** Щоб отримати форму W1 (4×8): (4×105)(105×8).
2. **Чому db — це сума, а не середнє?** Усереднення вже закладено в dZ2 через /N; b додається до кожного об'єкта, тож внески сумуються.
3. **Навіщо зберігати Z1, якщо є H?** Маску можна отримати і з H > 0 (результат однаковий), але Z1 — пряма відповідь «де ReLU була активна». Обидва варіанти коректні.
4. **Що зміниться, якщо втрата буде сумою, а не середнім?** Зникне /N у dZ2, і PyTorch треба налаштувати `reduction="sum"`.
5. **Навіщо транспонувати ваги при копіюванні в PyTorch?** `nn.Linear` обчислює x·Wᵀ + b і зберігає W як (out, in); у нас W має форму (in, out).
6. **Чому звірка втрати з PyTorch пройшла при помилці?** Помилка лише в backward.
7. **Чи можна замість чисельної перевірки обійтися лише PyTorch?** Можна, але чисельна перевірка не залежить від жодної бібліотеки autograd і перевіряє саме похідну вашої функції втрат.
8. **Що станеться без зсуву на максимум?** При великих логітах `exp` дасть inf, а втрата — nan.
